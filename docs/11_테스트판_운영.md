# 11. 일반 웹 테스트판 (Netlify + Supabase)

클로드 계정이 없는 부모도 쓸 수 있는 테스트판이에요. 화면은 claude.ai 판과 같아요. 여기에 **설문 결과 보내기(선택)**와 **운영자 화면**이 더해져요.

## 무엇이 어디에 있나

| 파일 | 하는 일 |
|---|---|
| `app/template.html` | 화면 원본. `WEB` 값이 있을 때만(일반 웹 판) 「운영자에게 결과 보내기」와 「보낸 설문 결과 지우기」가 보임 |
| `src/lib/survey.js` | 설문 문항과 해석 규칙. 앱과 운영자 화면이 같은 코드를 씀 |
| `app/admin.html` | 운영자 화면 원본 |
| `app/privacy.html` | 개인정보 수집·이용 안내 |
| `scripts/build-app.js` | `app/index.html`(claude.ai 판)과 `public/`(일반 웹 판: index·admin·privacy)을 함께 만듦 |
| `config/web.json` | Supabase 주소와 **공개 키**만 넣음. 비밀 키를 넣으면 빌드가 멈춤 |
| `netlify.toml` | Netlify가 `public/`을 그대로 올림. 빌드 명령 없음. 검색 노출 막음, 보안 헤더 |
| `supabase/schema.sql` | 표 3개(submissions, rate_log, admins), 접근 규칙(RLS), 매일 자동 삭제 |
| `supabase/functions/submit` | 결과 받기: 내용 검사, 반복 제출 제한(같은 곳에서 1시간 10번), 같은 내용 하루 중복 막기, 응답번호·삭제코드 발급, 다시 보내기 |
| `supabase/functions/delete` | 응답번호와 삭제코드로 지우기 (1시간 20번 제한) |

## 보내는 것 / 보내지 않는 것
- **보냄**
  - 출생연도, 관찰자(부모/교사)
  - 24문항 답, 고른 지원
  - 지원할 곳 1~3곳 (기관 id와 이름)
  - 원하는 교육 방향
  - 동의 버전, 시각
- **안 보냄**
  - 아이 별명, 이름·연락처
  - 문항별 예시 메모
  - 생활 질문 (건강·알레르기 포함)
  - 상담 기록, 출발지
- 분석 결과(잘하는 점, 필요한 지원, 교육 방향)는 저장하지 않아요. 운영자 화면이 답을 보고 앱과 같은 규칙(`survey.js`, `profile.js`)으로 그때그때 계산해요.
- 아이를 "○○형"처럼 유형으로 나누지 않아요. 통계는 교육 방향별, 필요한 지원별, 문항별로 세요.

## 지키는 장치
- 브라우저(공개 키)로는 submissions 표를 읽지도 쓰지도 못해요.
  - 쓰기는 서버 기능만 해요. 서버 기능은 Supabase가 서버 안에만 넣어 주는 비밀 키를 써요.
  - 읽기와 지우기는 admins 표에 등록된 로그인 계정만 할 수 있어요.
- 삭제코드는 원문을 저장하지 않아요. `sha256(응답번호:코드)` 값만 남겨서 운영자도 알 수 없어요.
- IP는 원문을 저장하지 않아요. 해시 값만 하루 동안 보관해요.
- 보관 기간은 2027-03-31까지예요. 매일 새벽 자동으로 지우고, 서버 기능이 불릴 때마다 한 번 더 지워요.
- 2026-11-01에 이 컨테이너에서 확인한 것
  - 로컬 Postgres에서 접근 규칙
    - 익명은 읽기·쓰기 모두 거부돼요.
    - 일반 로그인 계정은 0건만 보이고, 고치기와 관리자 추가는 거부돼요.
    - 관리자는 보기와 지우기가 돼요.
  - Deno + 가짜 DB로 서버 기능
    - 검사, 중복, 반복 제한(11번째부터 429), 다시 보내기, 틀린 코드, 지우기
  - 브라우저에서 화면 전체 흐름
    - 동의 안 하면 막힘 → 보내기 → 다시 보내기 → 지우기
    - 운영자 화면: 로그인, 집계, 필터, 상세, 지우기, 휴대폰 폭

## 처음 설정 (운영자가 한 번만)
1. **Supabase**: https://supabase.com 가입 → New project (지역: Northeast Asia (Seoul))
2. **SQL Editor** → `supabase/schema.sql` 내용을 통째로 붙여넣기 → Run
3. **Edge Functions** → Deploy a new function → Via Editor
   - 이름 `submit`: `supabase/functions/submit/index.ts` 붙여넣기 → Deploy
   - 이름 `delete`: `supabase/functions/delete/index.ts` 붙여넣기 → Deploy
   - 두 기능 모두 설정에서 **Verify JWT(JWT 확인)를 끔**. 부모는 로그인하지 않기 때문이에요. 대신 기능 안에서 검사해요.
4. **Authentication**
   - Sign In / Providers에서 **"Allow new users to sign up" 끄기**
   - Users → Add user → Create new user (관리자 이메일·비밀번호, Auto Confirm 켜기)
   - SQL Editor에서 schema.sql 맨 아래 6번 줄의 이메일을 바꿔 실행 → 관리자 등록
5. **Project Settings → API**
   - **Project URL**과 **publishable(또는 anon) key**를 개발 담당(클로드)에게 전달. 둘 다 공개용 값이에요.
   - **secret / service_role 키는 절대 전달하지 않아요.**
6. 클로드가 `config/web.json`을 만들고 빌드해서 올려요.
7. **Netlify**: https://netlify.com 가입 → Add new site → Import from Git → GitHub `gjna90/child` → 브랜치 선택
   - 빌드 설정은 비워 두면 돼요. `netlify.toml`이 `public/`을 올려요.
8. 사이트 주소가 나오면 Supabase → Edge Functions → Secrets에 `ALLOWED_ORIGINS=https://사이트주소.netlify.app`을 넣어요. 다른 사이트에서 보내는 걸 막아요.
   - 선택: `RATE_SALT=아무 긴 글자`

## 운영
- 운영자 화면: `https://사이트주소.netlify.app/admin.html`
- 주간 자동 갱신이 `public/`도 다시 만들어 올리면 Netlify가 자동으로 새로 배포해요.
- Supabase 무료판은 1주일 동안 쓰지 않으면 일시정지돼요. 대시보드에서 Restore를 누르면 다시 켜져요.
- 개인정보 안내 문구를 바꾸면
  - `app/privacy.html`의 버전을 고쳐요.
  - template의 `CONSENT_VER`도 고쳐요.
  - 서버 기능의 `CONSENTS` 목록에 새 버전을 더해요.
- 설문 문항을 바꾸면 서버 기능의 `SCALE`·`SUPPORT_KEYS`도 맞춰요. `test/survey.test.js`가 다르면 실패해서 알려 줘요.
