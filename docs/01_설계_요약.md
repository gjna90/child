# 우리 아이 맞춤 유치원·어린이집 탐색 — 설계 요약

기준: 2027학년도(변경 가능) · 아산시 배방읍·탕정면(+ 사용자가 인근 지역 추가) · 시간대 Asia/Seoul

---

## 1. 화면 흐름

```
첫 화면
 ├ "어디에서 출발하세요?"  (아파트명·동네·지도 찍기·현재 위치[요청 시])
 └ "무엇이 가장 중요하세요?" (통학시간·자연놀이·비용·돌봄… 중 고르고 순서 정하기)
        │  ※ 설문 없이 바로 검색 가능
        ▼
지도·기관 목록 ⇄ 필터·정렬·중요도
        │ (지도 핀 누르면 요약 카드)
        ▼
기관 상세 ── 관심 기관 담기 ── 나란히 비교(최대 4곳)
        │
        ├ 우리 아이 성향·생활 알아보기 (아이별, 날짜별 다시 작성)
        │       ▼
        │   결과: 강점·편한 조건·도움 필요 상황·확인할 지원·상담 질문·아직 못 본 부분
        │       ▼
        ├ 개인별 추천과 이유 (아이 A / 아이 B / 가족 전체 전환)
        ├ 설명회·모집 달력
        ├ 상담 체크리스트·방문 기록 → 추천에 반영
        ├ 자료 보관함 (공지·PDF·캡처 올리기 → 일정·조건 추출)
        └ 사용자 설정 (학년도, 기준 위치 여러 개, 내보내기·삭제)
```

모든 화면에 공통: 불러오는 중 / 결과 없음(완화할 조건 제안) / 자료 없음 / 수집 실패 상태.
주소·전화·홈페이지는 누르기 + 복사 버튼.

## 2. 데이터 구조 (요약)

**기관 공개정보** 와 **개인 데이터** 를 다른 테이블·권한으로 나눈다.

### 기관 공개정보 (모든 사용자 공통, 읽기 전용)
| 테이블 | 내용 |
|---|---|
| `institutions` | 공식 식별자, 유치원/어린이집, 공식 유형, 운영 상태, 주소·좌표, 지역 판정 |
| `facts` | 한 칸 = 값 + 단위 + 적용 학년도·연령 + 출처 + 문서 페이지 + 기준일 + 확인일 + 확인 상태 + 변경 이력 |
| `class_groups` | 기관이 부르는 반 이름, 공시 연령 구분, 대상 출생연도, 혼합 여부, 반 수·정원·현원, 학년도(현재/다음) |
| `staff` | 역할별 인원(원장·담임·보조·연장전담…) — 기관 전체와 반별 배치를 분리 |
| `programs` | 프로그램·자연활동: 대상 연령, 요일·횟수·시간, 필수/선택, 외부강사, 추가비용 |
| `costs` | 월·연·일회성, 필수/선택, 지원 적용 조건 |
| `admissions` | 모집 학년도, 게시일, 대상 출생연도, 우선·일반·추가모집, 쌍생아 처리 |
| `events` | 설명회 예약 시작·마감, 설명회, 접수, 발표, 등록 — 각각 따로 |
| `sources` / `documents` | 출처 종류(공식 공시·기관 안내·전문가·후기·제3자·사용자), 읽은 방식(원문/검색 요약/자막) |

`facts.status`: 확인됨 · 검색 요약만 확인 · 제3자 자료 · 사용자 입력 · 미확인 · 출처 간 불일치 · 과거 자료
→ 미확인은 `null`. 0원·0명·없음으로 바꾸지 않는다. 수집 실패 시 확인일을 바꾸지 않는다.

### 개인 데이터 (계정별, 본인만 접근)
`children`(별명·출생연도만 필수) · `surveys`/`survey_answers`(날짜별, 부모/교사 구분) ·
`origins`(기준 위치 여러 개, 정밀도 선택) · `family_conditions`(필수 조건) · `preferences`(기준·순서·중요도) ·
`favorites` · `consult_notes`/`visits`(자동 수집이 덮어쓰지 않음) · `applications`(사용자가 직접 관리하는 신청 상태)

모든 개인 테이블에 `user_id`를 두고, 데이터베이스 자체의 행 단위 권한(RLS)으로 본인 행만 읽고 쓰게 한다.

## 3. 연령반 규칙 (5세반 ≠ 만5세반)

- 만 연령반 = 학년도 − 출생연도 − 1 → 2027학년도: **2023년생 만3세 / 2022년생 만4세 / 2021년생 만5세**
- 옛 세는나이 표기 'N세반' = 만(N−2)세반 → 생활 표현 **'5세반' = 2027학년도 2023년생 = 만3세반**
- 숫자만 있는 반 이름('5세반')은 두 해석(2023년생 / 2021년생)을 모두 남기고, 출생연도·같은 기관의 다른 반 이름(6·7세반 존재 등)으로 판단. 확정 못하면 **'대상 여부 확인 필요'**.
- '5세 이상반 보유' = 만3세 이상 유아반이 하나라도 있음. **'우리 아이가 들어갈 반이 있음'** 은 따로 판정.
- 공시(현재 학년도) 반 구성 ≠ 다음 학년도 개설 예정 → 모집요강으로 확인.
- 코드: `src/lib/age.js`, 검증: `test/age.test.js`

## 4. 추천 규칙 (명시적 규칙, AI는 설명만)

### 4-1. 필수 조건 (점수와 분리)
각 조건 → **충족 / 불충족 / 미확인**
- 불충족이 하나라도 있으면 추천 목록에서 빠지고 '조건 불충족' 묶음에 이유와 함께 표시. 다른 장점으로 상쇄하지 않음.
- 미확인이 있으면 '추가 확인 후보' 묶음 + 확인할 질문.
- 예: 출생연도 지원 가능, 등하원 시간, 통학차량 또는 최대 통학시간, 방학 돌봄, 최대 예산, 꼭 필요한 생활 지원, 자녀 동시 이용.

### 4-2. 선호 기준 → 기준별 0~1 값
| 기준 | 0~1 변환 | 미확인일 때 |
|---|---|---|
| 이동시간 | 사용자가 정한 '괜찮은 시간(예: 10분)'=1, '최대(예: 30분)'=0, 그 사이 직선 | 계산에서 빼고 '조회 불가' 표시 |
| 비용 | 예산의 50% 이하=1, 예산=0.3, 예산 초과는 필수 조건에서 처리 | 계산에서 뺌 |
| 자연놀이 | 확인된 빈도: 주 3회 이상=1, 주 1~2회=0.6, 월 1~3회=0.3, 없음=0 | 계산에서 뺌(사진만으로 추정 금지) |
| 특성 태그(숲·놀이·몬테소리·언어…) | 원하는 태그 확인=1, 일부=0.5, 아님=0 | 계산에서 뺌 |
| 해당 반 규모 | 해당 연령 반 1학급당 원아수: 사용자 기준 이하=1, 기준×1.5=0 | 기관 전체 평균으로 대신하지 않음 |
| 설문 연동 지원 | 부모가 '중요'로 고른 지원 중 확인된 비율 | 상담 질문으로 연결 |
| 자녀 동시 이용 | 동시 입학 가능 확인=1, 불가=0 | 계산에서 뺌 |

### 4-3. 두 가지 모드
1. **우선순위대로 정렬**: 1순위 기준으로 묶음(예: 이동시간 5분 단위) → 같은 묶음 안에서 2순위 → 3순위… 미확인 기관은 해당 기준에서 순위를 매기지 않고 별도 '미확인' 표시.
2. **종합 추천**: 중요도 가중치 매우 중요=3, 중요=2, 참고=1.
   - 비교 지표 = Σ(가중치×값) ÷ Σ(확인된 기준의 가중치) × 100
   - **정보 확인 정도** = Σ(확인된 기준의 가중치) ÷ Σ(전체 가중치) — 지표와 따로 표시
   - 확인 정도 50% 미만 기관은 상위 목록에 올리지 않고 '정보 부족' 묶음으로 → 한 항목만 확인된 기관이 1위가 되는 것을 막음
   - 동점: 확인 정도 높은 순 → 이동시간 짧은 순 → 이름순
- 표시 문구: "선택하신 기준에 따른 비교 지표입니다." ('적합도 %', '적응 성공률' 표시 금지)
- 인기·팔로워·좋아요·홍보량은 쓰지 않음.

### 4-4. 설문 → 지원 → 기관 연결
```
관찰 답변 → 지원 필요 '잠정 제안' → 부모가 확인·중요도 선택 → 기관의 확인된 지원 정보 → 추천 이유 / 우려 / 상담 질문
```
예: 문항 10(전환 예고가 도움) → `전환 안내` 지원 → 기관 일과·전환 방식 확인됨이면 이유, 미확인이면 질문 "활동을 바꿀 때 미리 알려주시나요?"
'관찰 기회 없음'은 점수에 넣지 않고 '아직 관찰하지 못한 부분'에 표시. 성향 하나로 교육 방식을 정답 처리하지 않음.

### 4-5. 다자녀·쌍둥이
아이별로 필수 조건·지표를 따로 계산 → 가족 전체 보기에서는 **두 아이 모두 필수 조건 충족** 기관만 추천, 각 아이의 우려를 가리지 않고 나란히 표시. 같은 반/다른 반은 정답 처리하지 않음. 쌍생아 모집 규칙은 해당 기관·학년도 모집요강 근거로만 안내.

## 5. 기술 구성 (권장 기본값)

| 역할 | 선택 | 이유 |
|---|---|---|
| 웹앱 | Next.js (React) | 모바일·PC 공용, 서버 쪽에서 비밀키 보관 가능 |
| 데이터베이스·로그인·권한 | Supabase (Postgres + 로그인 + 행 단위 권한) | 사용자별 분리를 데이터베이스가 강제 |
| 지도·주소검색 | 카카오맵 JavaScript SDK + 로컬(주소·키워드) API | 국내 아파트명·주소 검색에 강함 |
| 자동차 경로 | 카카오모빌리티 길찾기 API (후보) | 국내 도로 기준 |
| 도보 경로 | TMAP 보행자 경로 API (후보) | 카카오는 공개 도보 경로 API가 없음(확인 필요) |
| 기관 자료 | 유치원알리미 Open API·일괄 다운로드, 어린이집정보공개포털 Open API 또는 공공데이터포털 파일 | 공식 공시 |
| 문서 추출·설명 | Claude API (선택) | 공지·PDF에서 일정 추출, 확인된 결과 설명 |
| 배포 | Vercel 또는 Netlify | 무료 단계로 시작 가능(상업적 이용 조건은 확인) |

각 API의 무료 사용량·요금·이용 조건은 이 환경에서 원문을 열지 못해 **확인 필요**로 둔다(1단계 보고서 참고).

## 6. 단계별 구현 계획

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| **1. 데이터 확보 검증** (지금) | 출처별 제공 항목·접근 방법 확인, 명부 수집·정리 코드, 연령반 판별, 3~5곳 시험 수집 | 공식 명부로 기관 수 집계, 포함·제외·확인 필요 분류 |
| 2. 지도·검색·비교 | 기준 위치, 지도·목록, 필터(OR/AND 규칙 표시), 상세, 4곳 비교 | 실제 기관 자료로 동작 |
| 3. 설문 | 아이별 24문항 + 생활 질문, 날짜별 저장, 결과·상담 질문 | 새로고침 후에도 유지 |
| 4. 연동 추천 | 필수 조건, 중요도, 두 모드, 근거·미확인 표시 | 규칙 문서와 테스트 일치 |
| 5. 설명회·상담·자료 | 공지·PDF 추출, 달력, 상담 기록 반영 | 과거/현재 학년도 분리 |
| 6. 다중 사용자·운영 | 로그인, 권한 검사, 정기 수집·변경 감지, 백업·삭제, 배포 | 다른 계정 자료 접근 불가 테스트 |
